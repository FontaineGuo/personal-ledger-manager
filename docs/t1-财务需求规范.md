# t1 财务需求规范（基于 2026下半年.xlsx 真实账本分析）

> 数据来源：交易流水 286 条（2026-06-25 ~ 2026-10-29）、余额快照 48 行（9 账户 × 5 个账期）、配置表 1 张。
> 收入 38 笔共 ¥84,372.41；支出 248 笔共 ¥30,895.36。

## 1. 现有记账体系分析

### 1.1 表结构
- **交易流水**：`日期 | 账期 | 方向(收入/支出) | 分类 | 金额 | 账户 | 备注`
- **余额快照**：`账期 | 账户 | 月初余额 | 月末余额`
- **配置表**：`支出分类 | 收入分类 | 账户列表` 三列并列的白名单

### 1.2 分类体系（扁平单级，来自配置表白名单）
- 支出 8 类：数码电器、日用百货、餐饮美食、交通出行、文化休闲、医疗健康、旅行、投资、杂项（实际 9 个）
- 收入 5 类：工资收入、股权收入、投资收益、额外/其他、报销收入
- 特点：**无二级分类**，粒度靠备注文本补充（如"信用卡分期：漫步者耳机 话费充值"）

### 1.3 账户体系（8 个真实账户）
银行卡：中行、招行、建行、农行、成都银行；支付账户：微信余额、支付宝余额、余额宝。
流水中的账户分布：中行 164、微信余额 71、招行 37、建行 9、支付宝余额 5。

### 1.4 账期与勾稽规则（实测归纳）
- **账期 ≠ 自然月**：交易按"账期"列归属（如 6/25 的工资归 2026-06，7/1 起归 2026-07），账期切换点在每月末附近（工资发放日）。
- **信用卡大额走招行**，备注以 `信用卡分期：` 或 `信用卡：` 前缀标识；**分期未拆分为多笔**，一次性计入支出（分期后续期数未逐月入账，属已知简化）。
- **月末勾稽**：月末余额 = 月初余额 + 当期该账户流入 − 流出（余额快照可逐账户验证）。
- 微信余额存在"补差"类小额调整（如"11月微信补差 0.61"）。

### 1.5 记账习惯
- 备注承载关键语义：分期标识、AA 制（"饭AA"）、团购、报销、工资拆分说明。
- 高频支出：餐饮美食（¥5,361）、日用百货（¥4,658）、投资转出（¥6,723）、杂项（¥5,832）、数码电器（¥4,251）。

## 2. 对话式记账必须支持的核心用例

| # | 用例 | 账本依据 | 对话要点 |

## 3. 数据规范

### 3.1 交易记录必填/选填字段
| 字段 | 必填 | 规则 |
|------|------|------|
| date | 是 | ISO YYYY-MM-DD |
| period | 是 | 账期 YYYY-MM，默认= date 所在月（若 date 日 ≥ 25 且属下月工资周，需确认；MVP：取 date 所在月，允许显式覆盖） |
| direction | 是 | 枚举 收入/支出 |
| category | 是 | 必须在配置表白名单内，否则追问 |
| amount | 是 | >0，两位小数 |
| account | 是 | 必须在 8 账户白名单内，否则追问 |
| note | 否 | 原样保留，分期前缀"信用卡分期："由对话生成 |

### 3.2 配置白名单（与配置表同步，可维护）
- 支出分类：数码电器/日用百货/餐饮美食/交通出行/文化休闲/医疗健康/旅行/投资/杂项
- 收入分类：工资收入/股权收入/投资收益/额外/其他/报销收入
- 账户：中行/招行/建行/农行/成都银行/微信余额/支付宝余额/余额宝

### 3.3 校验规则
1. **白名单校验**：分类、账户必须在配置表内；对话中新分类需用户确认后写入配置。
2. **余额勾稽**：每账期末，对每账户校验 `月末 = 月初 + Σ收入 − Σ支出`，不平则报告差异明细。
3. **幂等防重**：同一对话会话内，同一 (date, amount, account, category, note) 组合 60 秒内重复提交需确认。
4. **金额合法性**：>0 且 < 1,000,000；收入分类不得出现在支出方向（方向由分类联动推断，工资/报销→收入，其余→支出）。

### 3.4 MVP 边界（明确不做）
- 不拆信用卡分期期数计划（保持与现状一致的一次性入账）
- 不做多级分类、多币种、预算管理（列为进阶项）
